# 数据质量规范（Data Quality）

> **数据准确性是本项目最高优先级。** 本文档是 `AGENTS.md` 第 2 节的详细展开，所有数据相关实现与评审必须以此为准。
> 最后更新：2026-08-19

## 1. 铁律（强制性，不可协商）

1. **禁止把搜索引擎摘要当作精确实时价或收盘价。** 搜索引擎摘要可能滞后、截断或错误，只能作为线索，不能入库、不能用于计算、不能展示为行情。
2. **每条行情记录必须包含以下字段**，缺一不可：

   | 字段 | 说明 |
   | --- | --- |
   | `symbol` | 证券代码（含后缀，如 600519.SH / 00700.HK） |
   | `market` | 市场（SH / SZ / HK） |
   | `trade_date` | 交易日（YYYY-MM-DD） |
   | `quote_time` | 报价/行情时间 |
   | `fetched_at` | 抓取入库时间（本地时间，Asia/Shanghai） |
   | `source` | 数据来源（akshare / tushare / tdximp / manual_verified / ...） |
   | `price_type` | 价格类型（open / high / low / close / prev_close / ...） |
   | `adjustment` | 复权（none / qfq / hfq） |
   | `is_delayed` | 是否延时行情（0/1） |
   | `raw_value` | 原始值（适配器原样返回，可追溯） |
   | `normalized_value` | 标准化后的数值（统一单位、剔除异常） |

3. **双源校验**：关键收盘数据（指数收盘、重点持仓收盘）尽量从两个独立来源获取比对；**来源冲突时标记异常，不输出确定性结论**。
4. **人工确认**：用户通过通达信或券商终端人工确认的价格记录，`source` 标记为 `manual_verified`，优先级最高。
5. **缺失即显缺失**：数据缺失时明确显示"缺失/无数据"，**不能用历史缓存伪装成当天数据**；缓存必须带时间戳并如实标注。
6. **来源与时间展示**：所有行情页面必须显示数据来源和截至时间。
7. **适配器测试**：后续为数据适配器编写四类质量测试——延迟（is_delayed 正确性）、空值、字段变化（上游字段变更检测）、来源冲突（双源不一致检测），存放于 `tests/data/`。

## 2. 字段取值规范

- `symbol` 后缀：A股 `600519.SH`（沪）`000001.SZ`（深）；港股 `00700.HK`；ETF 遵循所在交易所后缀（`510300.SH`、`159915.SZ`）。
- `price_type`：`open` / `high` / `low` / `close` / `prev_close` / `adj_close` 等，不允许模糊值。
- `adjustment`：`none`（不复权，默认）/ `qfq`（前复权）/ `hfq`（后复权）；**复权方式不一致的数据禁止混算**。
- `is_delayed`：实时 `0`，延时 `1`；无法确认时按延时处理并标记。
- 单位：A股/ETF 价格单位元，港股价格单位港元；`normalized_value` 统一为数值类型，`raw_value` 保留原始字符串/数值。

## 3. 来源优先级与冲突处理

1. `manual_verified`（人工确认）> 双源一致的自动来源 > 单源自动来源 > 无来源数据。
2. 双源冲突（如收盘价偏差超过阈值，阈值 Phase 1 定义并登记 DECISIONS.md）：记录两条数据并标记 `conflict`，界面显示异常提示，**不输出确定性结论**。
3. 单源数据可用，但必须完整标注 `source` 与 `fetched_at`，不得冒充多源。

## 4. 缺失与缓存

- 数据库/缓存记录必须包含写入时间戳；读取时校验数据日期与当日关系。
- 非交易日查询当日行情：返回"非交易日"状态，不得返回最近交易日数据冒充当日。
- 交易日数据未抓取成功：显示"缺失（未抓取/抓取失败）"，并给出重试/手动录入入口。

## 5. 溯源与审计

- `data/raw/` 保留适配器下载的原始内容，`data/processed/` 只放清洗结果，二者通过 `fetched_at` + `source` 关联。
- 任何展示给用户的数值都必须能回溯到 `raw_value` 与来源。

## 6. 验收清单（实现数据功能时逐项核对）

- [ ] 行情记录 11 字段齐全
- [ ] 关键收盘数据双源校验，冲突有异常标记
- [ ] `manual_verified` 支持且优先级最高
- [ ] 缺失显示为缺失，无缓存冒充
- [ ] 页面显示来源与截至时间
- [ ] tests/data/ 四类质量测试存在且通过（延迟、空值、字段变化、来源冲突）
